## 2. Core Concepts Explained

### A. JSP Translation & Lifecycle

A JSP is not executed as a static HTML file; it is compiled into a Java Servlet class by the JSP container (Tomcat Jasper):

1. **Translation Phase:** The container parses `.jsp` and generates a Java source file (`<jsp_name>_jsp.java`) extending `org.apache.jasper.runtime.HttpJspBase`.
2. **Compilation Phase:** The Java source is compiled by `javac` into bytecode (`<jsp_name>_jsp.class`).
3. **Class Loading & Instantiation:** The compiled servlet class is loaded into the JVM and instantiated.
4. **Lifecycle Methods:**
   - `jspInit()`: Invoked once when the JSP is initialized. Custom initialization code can be written inside `<%! void jspInit() { ... } %>`.
   - `_jspService(HttpServletRequest, HttpServletResponse)`: Automatically generated by the container to handle each incoming client request and write the HTML response.
   - `jspDestroy()`: Invoked when the JSP is removed from service for cleanup.

### B. Expression Language (EL)

Expression Language provides a clean, concise syntax (`${...}`) to access server-side data without writing messy Java scriptlets (`<%= ... %>`):

- **Syntax:** `${name}`, `${email}`, `${course}`, `${age}`.
- **Scope Hierarchy:** When an EL variable is evaluated, the container searches attribute scopes in this order:
  1. `Page` scope
  2. `Request` scope (`request.getAttribute(...)`)
  3. `Session` scope (`session.getAttribute(...)`)
  4. `Application` (ServletContext) scope
- **Null Safety:** If an attribute does not exist or is null, EL prints an empty string instead of throwing a `NullPointerException`.

### C. Request Parameters vs. Request Attributes

| Feature | Request Parameter (`request.getParameter`) | Request Attribute (`request.setAttribute`) |
| :--- | :--- | :--- |
| **Origin** | Sent by the client / browser (HTML Form inputs or URL query strings). | Created server-side in Java code by Servlets/Filters. |
| **Data Type** | Always `String` or `String[]`. | Any Java `Object`. |
| **Mutability** | Read-only. | Read / Write / Remove. |
| **Purpose** | Capturing client user input. | Passing processed server-side data to the View (JSP). |

### D. `RequestDispatcher.forward()` vs. `HttpServletResponse.sendRedirect()`

- **`RequestDispatcher.forward(request, response)`:**
  - **Server-side internal transfer:** Tomcat transfers execution to `result.jsp` internally.
  - **Single Request:** Keeps the original `HttpServletRequest` and `HttpServletResponse` alive, preserving all `request.setAttribute()` values.
  - **Browser URL:** The browser address bar remains on the controller route (`/hello`).
- **`sendRedirect(url)`:**
  - **Client-side round-trip:** The server sends HTTP 302 with a `Location` header, instructing the browser to make a brand-new GET request.
  - **Request Scope Lost:** All request attributes are destroyed upon completion of the initial request.

## 5. Viva Questions & Answers (From Professor's PDF)

**Q1: What does JSP stand for?**  
> **Ans:** JavaServer Pages.

**Q2: Is a JSP executed directly as HTML?**  
> **Ans:** No. It is translated into a Java Servlet by the JSP container (e.g. Apache Jasper in Tomcat), compiled into bytecode, and executed.

**Q3: What is the role of JSP in web architecture?**  
> **Ans:** Primarily presentation/view generation (generating dynamic HTML for the client).

**Q4: What is the role of a Servlet?**  
> **Ans:** Request processing, validation, business logic dispatching, and controller logic.

**Q5: What is EL?**  
> **Ans:** Expression Language (`${...}`), used to access server-side attributes stored in page, request, session, or application scopes without writing scriptlets.

**Q6: What does `request.setAttribute()` do?**  
> **Ans:** Stores key-value data inside the request scope so downstream resources (like a forwarded JSP) can read it.

**Q7: What does `RequestDispatcher.forward()` do?**  
> **Ans:** Forwards the current request and response server-side to another resource (such as a JSP) within the same web application.

**Q8: What is `jspInit()`?**  
> **Ans:** The JSP lifecycle method called once when the JSP is initialized.

**Q9: What is `_jspService()`?**  
> **Ans:** The container-managed lifecycle method that services client requests and generates dynamic response output.

**Q10: What is `jspDestroy()`?**  
> **Ans:** The JSP lifecycle cleanup method executed before the JSP servlet is unloaded.
